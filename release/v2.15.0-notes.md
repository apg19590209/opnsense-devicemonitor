# Device Monitor v2.15.0 — Email Log, HA peer viewing and message formatting

## Changes

- **Email Log page.** Services → Device Monitor → **Email Log** lists every notification this node
  submitted: time, node, type, recipient, subject and status, with search, type/status filters,
  Active/Deleted/All entries visibility, pagination and a UTC-labelled CSV export. Records live in
  their own database (`/var/db/devicemonitor/email_log.db`) and never in `devices.db` or the mail
  queue; 30-day retention is a separate action.
- **One message view.** The subject is the row action. It opens a viewport-safe dialog with the
  metadata, the captured body as plain text and the complete delivery timeline under **Delivery
  details** (with the recorded event count). An empty subject shows **No subject**.
- **Status means what it says.** Submission, queue, relay acceptance, failure and unknown are
  distinct; **Relay accepted** (DSN 2.0.0) is never presented as inbox receipt. Out-of-band
  observation correlates the exact Message-ID with Postfix's own records, so a message that leaves
  the queue immediately is still resolved from the dated processing log.
- **Bulk soft deletion.** Select local entries on the page (header checkbox for the current page) and
  use **Delete selected (n)**, or remove every active local entry with **Delete all local entries**.
  Entries are hidden, not destroyed: they stay restorable from the Deleted view until normal
  retention removes them. Actual emails and mail queues are unaffected. Confirmations follow the
  standard OPNsense dialog and the destructive action needs an explicit checkbox.
- **HA peer viewing.** Local, Peer and All nodes tabs with one shared column layout; each node is
  named as hostname — management IP — role, and rows keep the role recorded when the email was sent.
  Peer access uses a dedicated read-only privilege (`Services: Device Monitor (email log peer read)`)
  covering only the peer listing and message endpoints; remote entries cannot be deleted, restored or
  selected. Peer transport requires HTTPS with verified trust and an optional CA certificate.
- **Message formatting.** HTML bodies are converted to readable text structurally: table rows render as
  compact label/value lines, paragraph breaks are preserved, scripts and remote images are removed and
  entities are decoded once. Previously stored bodies keep their original formatting.
- **Timestamps.** Stored in UTC, shown in the browser's timezone with its own suffix (for example
  AEDT/AEST) and exported as UTC.

This release also carries the pre-release price-gate correction (provider UTC windows with boundary
tests) used by the development harness.

## Upgrade

`install-unattended.sh` accepts 2.8 through 2.13.3 and 2.14.0 as predecessors, keeps the existing
configuration and databases, and reports `INSTALL_OK` with a rollback backup directory.
