# Device Monitor v2.11

## Changes

- Targeted Nmap scan history now writes through a single asynchronous writer thread. `run_targeted_scan_with_history()` hands a completion payload to `enqueue_db_write()` instead of writing it inline on the scan thread, so the SQLite write lock and its fsync no longer run inside the scan path. One process-wide daemon thread (`dm-db-writer`) owns a single long-lived connection and commits one transaction per job.
- The synchronous path is retained as a fallback: if the writer thread cannot be started, the caller performs the original inline write, so recorded history is never lost by a failure to defer.
- The pre-scan history `INSERT` (whose `lastrowid` is required by the port rows) and the abort/failure `UPDATE` remain synchronous by design.
- Queue draining is deterministic: `flush_db_writes()` blocks until every accepted job has been committed, and is called from `atexit` and at the end of `full_scan()`.
- Accepted risk (recorded as `DECISIONS.md` 37): a job that is queued but not yet committed is lost if the process is killed without running `atexit` — `SIGKILL`, an OOM kill, or a supervisor timeout that escalates to `SIGKILL`. Only `nmap_scan_history` and `nmap_scan_ports` are deferred; no device, configuration or notification state is affected.
- This release changes no user-visible interface. The version metadata is bumped to 2.11 so the installer, the manifest and the installed payload agree on one release identity.

## Language support

Unchanged from v2.10. Catalogues are installed and compiled for German (`de_DE`), Spanish (`es_ES`), French (`fr_FR`), Italian (`it_IT`), Japanese (`ja_JP`), Dutch (`nl_NL`), Portuguese (`pt_BR`), Russian (`ru_RU`) and Simplified Chinese (`zh_CN`), alongside English (`en_US`) and Czech (`cs_CZ`). The known Dutch limitation is unchanged: Dutch cannot be selected from `System → Settings → General → Language`, because OPNsense's own language list does not offer it.

## Installation

Download the `dm-v2.11-runtime.tar.gz` release asset. It contains only the installer and plugin runtime sources. Extract it on OPNsense and run `sh install.sh --host EXACT_FIREWALL_HOSTNAME`. The installer digest-pins and verifies `release/v2.11-runtime.manifest` (38 rows), checks the installed predecessor (2.8, 2.9 and 2.10 are supported), takes a retained rollback backup, verifies every installed file after writing, restarts `configd`, and restarts the Device Monitor daemon if it was running. Use `--check` for a preflight that changes nothing.

Existing device history and configuration are preserved. The installation backup remains on the firewall under `/var/backups/devicemonitor/`. No user database, configuration, passwords, or backups are included in the release asset.

## Release identity

`release/v2.10-runtime.manifest` is retained byte-unchanged as the v2.10 release artifact. `release/v2.11-runtime.manifest` is a separate 38-row payload cut from this tree; the three rows that differ from v2.10 are `src/opnsense/scripts/OPNsense/DeviceMonitor/scan_network.py` (the deferred-write change), `src/opnsense/mvc/app/models/OPNsense/DeviceMonitor/defaults.json` (version 2.10 to 2.11) and `src/etc/inc/devicemonitor_locale.inc` (a comment naming the guarded manifest). This file is not itself a manifest row.
