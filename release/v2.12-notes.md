# Device Monitor v2.12

## Changes

- **Scan cycles no longer abort.** The deferred history writer and the targeted-scan
  queue bookkeeping both wrote with the driver's 5 s default timeout, so a busy
  database raised `database is locked`. That exception aborted `full_scan()` before
  `nmap_scan_attempts`/`nmap_next_attempt` were stored, which meant the retry
  backoff never engaged and the head of the queue (ordered by `first_seen`) was
  rescanned every cycle. Every connection now carries `timeout=30` plus
  `PRAGMA busy_timeout`, the drain flushes the writer before updating a queue row,
  and each targeted scan is wrapped so a failure still records its backoff.
- **Alerts are state-change notifications.** A targeted scan only mails when the
  open-service inventory differs from the newest successful scan for that device;
  unchanged scans are still recorded in history with `email_sent=0`. Service
  alerts already deduplicated on transitions and are unchanged.
- **User-selectable repeat interval.** Each email category can repeat an unchanged
  state after 0 (default, never), 5, 10, 15, 30, 45 or 60 minutes, or any custom
  value up to 1440: `email_reminder_scan`, `email_reminder_service`,
  `email_reminder_identity`, `email_reminder_new_device`.
- **A new MAC at a known address is an identity change, not a new device.**
  `detect_mac_rotation()` compares the address against a snapshot of its known
  owner; a randomised (locally administered) MAC always counts as a rotation, a
  vendor MAC only while the previous owner was seen within
  `MAC_ROTATION_WINDOW_HOURS` (168 h). Rotations record an `IP_IDENTITY_CHANGED`
  event instead of mailing a new-device alert or queueing a scan.
- **Identity conflicts can be emailed.** `identity_email_enabled` is now read: a
  second leg (`notify_identity_mail.php`) sends the conflict table through the
  configured mail transport, independently of the existing webhook leg.
- **One alert source in an HA pair.** The CARP verdict is evaluated once per cycle
  and gates every outbound alert (identity, new device, service, targeted scan and
  the visibility sweep), so a standby no longer duplicates the MASTER's mail or
  pushes. Detection, history and the database still run on both nodes.
- **Visibility priming is unchanged by default** (one ICMP echo per monitored
  address per cycle). `visibility_prime_interval` optionally rate limits it and
  skips addresses Hostwatch already observed; a CARP BACKUP never primes.
- **Deployment is git-only and self-checking.** `deploy/` carries
  `publish-devicemonitor.sh` (builds a payload from a git ref), the on-box
  installer `deploy-devicemonitor.sh` (hash-gated, backs up, records
  `/var/db/devicemonitor/deployed.manifest`) and
  `verify-devicemonitor.sh`, which reports missing, modified or unversioned plugin
  files and runs daily from `/etc/cron.d/devicemonitor-drift`.
- **About tab reports one version.** Both the badge and the "Features and
  Enhancements" heading now come from `defaults.json`; the heading was a hardcoded
  `v2.10` string.
- **Version metadata is bumped to 2.12** so the installer, the manifest and the
  installed payload agree on one release identity.

## Language support

Unchanged from v2.11. Catalogues are installed and compiled for German (`de_DE`),
Spanish (`es_ES`), French (`fr_FR`), Italian (`it_IT`), Japanese (`ja_JP`), Dutch
(`nl_NL`), Portuguese (`pt_BR`), Russian (`ru_RU`) and Simplified Chinese
(`zh_CN`), alongside English (`en_US`) and Czech (`cs_CZ`). The known Dutch
limitation is unchanged: Dutch cannot be selected from
`System → Settings → General → Language`, because OPNsense's own language list
does not offer it.

## Installation

Download the `dm-v2.12-runtime.tar.gz` release asset. It contains only the
installer and plugin runtime sources. Extract it on OPNsense and run
`sh install.sh --host EXACT_FIREWALL_HOSTNAME`. The installer digest-pins and
verifies `release/v2.12-runtime.manifest` (41 rows), checks the installed
predecessor (2.8 through 2.11 are supported), takes a retained rollback backup,
verifies every installed file after writing, restarts `configd`, and restarts the
Device Monitor daemon if it was running. Use `--check` for a preflight that
changes nothing.

Existing device history and configuration are preserved. The installation backup
remains on the firewall under `/var/backups/devicemonitor/`. No user database,
configuration, passwords, or backups are included in the release asset.

## Release identity

`release/v2.11-runtime.manifest` is retained byte-unchanged as the v2.11 release
artifact. `release/v2.12-runtime.manifest` is a separate 41-row payload cut from
this tree: the 39 v2.11 rows with refreshed digests, plus
`src/opnsense/scripts/OPNsense/DeviceMonitor/notify_identity_mail.php` and
`src/opnsense/scripts/OPNsense/DeviceMonitor/verify-devicemonitor.sh`. This file
is not itself a manifest row.
